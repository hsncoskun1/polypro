# v0.3.1 — Discovery Trigger API Shell

## Summary

Exposes the discovery service as a single HTTP endpoint: `POST /api/v1/discovery/trigger`. Accepts a list of raw market items and an optional `source_name`, runs the discovery pipeline via `run_discovery_service()`, and returns a `DiscoveryTriggerResponse` with summary, source_name, and ran_at. No real source integration, no auth, no scheduler — endpoint wiring only.

## API Contract

**Endpoint:** `POST /api/v1/discovery/trigger`

**Request body:**
| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `source_name` | `str` | `"unknown"` | Metadata label for the run |
| `items` | `list[RawMarketItemSchema]` | `[]` | Raw market items to process |

**Response: `DiscoveryTriggerResponse`**
| Field | Description |
|-------|-------------|
| `summary.added_count` | Markets successfully added |
| `summary.skipped_duplicate_count` | Duplicate market_id collisions |
| `summary.skipped_invalid_count` | Normalization or timeframe failures |
| `summary.total_seen` | Total raw items received |
| `source_name` | Echo of caller-supplied label |
| `ran_at` | UTC datetime of execution |

## Architecture

```
POST /api/v1/discovery/trigger
         │
         ▼
  trigger_discovery()        ← v0.3.1
         │
         ▼
  run_discovery_service()    ← v0.3.0
         │
         ▼
    run_pipeline()           ← v0.2.8
```
