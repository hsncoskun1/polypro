# v0.3.17 — Discovery Run Status Shell

## Summary

Adds run lifecycle state tracking to the discovery trigger and a new `GET /api/v1/discovery/status` endpoint. Operators can query whether a run is in progress, when the last run finished, whether it succeeded or failed, and the last result summary or error message.

## Changes

| File | Change |
|------|--------|
| `backend/app/core/run_status.py` | New file — `DiscoveryRunStatus` dataclass |
| `backend/app/main.py` | Attach `DiscoveryRunStatus` instance to `app.state.discovery_run_status` at startup |
| `backend/app/api/discovery.py` | Status lifecycle in trigger; new `GET /status` endpoint |
| `backend/app/api/schemas/discovery.py` | New `DiscoveryRunStatusResponse` schema |
| `backend/tests/api/test_discovery_api.py` | 7 new run status tests |

## Status Lifecycle

| Event | Fields Updated |
|-------|---------------|
| Run starts | `is_running = True`, `last_error = None` |
| Run succeeds | `is_running = False`, `last_finished_at`, `last_success_at`, `last_result_summary` set |
| Run fails (HTTPException) | `is_running = False`, `last_finished_at` set, `last_error` set |

## Status Endpoint

`GET /api/v1/discovery/status` — no auth required — returns:

```json
{
  "is_running": false,
  "last_finished_at": "2026-04-02T12:00:00Z",
  "last_success_at": "2026-04-02T12:00:00Z",
  "last_result_summary": {"added_count": 3, ...},
  "last_error": null
}
```

## Design Decisions

- `DiscoveryRunStatus` is a plain dataclass on `app.state` — no persistence, resets on restart
- `last_error` cleared on run start; set in `except HTTPException` branch
- `is_running` always set to `False` in `finally` — consistent with run guard release
- Status endpoint requires no auth — read-only, no sensitive data
