# v0.5.2 — Force Sell Pack

## Summary

Introduces the force sell evaluator as a dedicated decision layer within exit policy.
Entry/fill-based adverse move (NOT PTB-based). Three independent conditions: time,
pnl-loss, and adverse delta. Any/all combinator for multi-condition scenarios.
No persistence, no PnL accounting, no risk engine in scope.

## Force Sell Conditions

| Condition | Trigger |
|-----------|---------|
| `force_sell_time` | time_remaining ≤ force_sell_time_seconds |
| `force_sell_pnl_loss` | current_pnl < 0 |
| `force_sell_entry_delta` | adverse_move ≥ force_sell_entry_delta_threshold |

## Adverse Move Calculation (Side-Aware)

| Side | Formula |
|------|---------|
| YES / UP | adverse_move = entry_fill_price − current_price |
| NO / DOWN | adverse_move = current_price − entry_fill_price |

## Reason Codes

| Reason | When |
|--------|------|
| `force_sell_time` | Only time enabled and triggered |
| `force_sell_pnl_loss` | Only pnl-loss enabled and triggered |
| `force_sell_entry_delta` | Only delta enabled and triggered |
| `force_sell_combined_any` | 2+ enabled, "any" combinator, at least 1 triggered |
| `force_sell_combined_all` | 2+ enabled, "all" combinator, all triggered |
| `` (empty) | No trigger |

## Design Decisions

| Decision | Rationale |
|----------|-----------|
| Entry/fill-based, NOT PTB-based | Binding project decision |
| Side-aware adverse move | YES/NO have opposite adverse directions |
| Single vs combined reason codes | Clear auditability — single reason for 1 enabled condition |
| Separate from execution | Evaluator produces decision; execution applies it |
| Never returns None | All paths return ForceSellDecision |
| Persistence | NOT in scope — v0.5.3 |
| PnL accounting | NOT in scope |
