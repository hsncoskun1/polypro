# v0.3.11 — Timeframe Mapping Integration Shell

## Summary

Wires `map_end_date_to_timeframe()` into the client/payload chain. `end_date` ISO 8601 strings from Polymarket rows are now converted to `Timeframe` enum values before entering `RawPayloadItem`. Past dates and unparseable strings raise `TimeframeMappingError` openly — no silent fallback.

## Changes

| File | Change |
|------|--------|
| `backend/app/adapters/external_payload.py` | `map_to_raw_payload_item()` now calls `map_end_date_to_timeframe(end_date)` and uses `timeframe.value` in `RawPayloadItem` |
| `backend/app/api/discovery.py` | Trigger endpoint builds `RawPayloadItem` directly (items arrive with Timeframe strings, not ISO dates) |
| `backend/tests/adapters/test_external_payload.py` | Updated test data to ISO dates; added past-date and unparseable-date error tests |
| `backend/tests/services/test_discovery_client.py` | Updated test data to ISO dates; added `TimeframeMappingError` propagation tests |

## Integration Chain (post-v0.3.11)

```
PolymarketClient.fetch()
    → map_client_rows_to_payloads()    [dict → PolymarketMarketPayload]
    → map_to_raw_payload_item()        [calls map_end_date_to_timeframe(end_date)]
    → RawPayloadItem.timeframe = "1D" / "1W" / "1M" / "3M"
    → PayloadDiscoveryAdapter
    → run_discovery_service()
```

## Error Behaviour

| Input | Result |
|-------|--------|
| Valid future ISO date | `Timeframe` enum value used |
| Empty `end_date` | `ExternalPayloadMappingError` |
| Past ISO date | `TimeframeMappingError` propagates |
| Unparseable string | `TimeframeMappingError` propagates |

## Design Decisions

- `map_to_raw_payload_item()` is the integration point — keeps external payload contract intact
- `TimeframeMappingError` propagates openly from `discovery_client.py` (not caught)
- Trigger API endpoint decoupled: receives Timeframe enum strings directly, bypasses ISO date conversion
- No silent fallback anywhere in the chain
