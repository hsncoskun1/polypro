# Release Notes — v0.8.1 Production Client Operational Hardening Pack

**Version:** v0.8.1
**Branch:** feat/v0.8.1-production-client-operational-hardening-pack
**Status:** In progress

## Summary

Operational hardening of the production exchange client. Establishes timeout policy,
retry policy, exception normalization, operation context (correlation/idempotency),
safe logging/redaction, and response validation models. No real network calls.
Seam points remain. Fail-closed behavior enforced throughout.

## Behavior

- Timeout errors normalize to `client_timeout` error code, retryable=True
- Retryable exceptions classified separately from terminal exceptions
- Unknown exceptions always terminal_failure=True (fail-closed)
- correlation_id and idempotency_key carried in ClientOperationContext
- Sensitive fields (api_key, secret, signature, token, raw_payload, etc.) redacted in logs
- Missing required response fields → validation_passed=False, fail-closed
- terminal_failure=True is a valid path and bypasses status field requirement
