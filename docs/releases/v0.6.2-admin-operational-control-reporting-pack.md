# v0.6.2 — Admin Operational Control + Reporting Pack

## Summary

Introduces admin-specific operational control surface and extended reporting foundation.
AdminControl models safe stop, scheduler control, global disable, config reload/reset.
AdminReportSnapshot provides broader financial and operational visibility than user-facing plane.
Blocked trade/rule/risk events, execution fills, claim events, operational alerts.
Turkish admin label mapping (24 keys).
No frontend, no new trading logic, no risk/accounting changes.

## AdminControl Fields

| Field | Description |
|-------|-------------|
| `safe_stop_active` | Halts new entries; existing trades complete normally |
| `safe_stop_reason` | Why safe stop was triggered |
| `scheduler_enabled` | Whether discovery/trigger scheduler is running |
| `global_disable_active` | Emergency hard stop of all activity |
| `config_reload_available` | Whether config reload is allowed |
| `config_reset_available` | Whether config reset is allowed |

## Design Decisions

| Decision | Rationale |
|----------|-----------|
| AdminControl is a separate model from snapshot | Control state is independent of reporting data |
| Assembler does not compute | All values come from upstream domain evaluators |
| Runtime state not directly modified | Control actions are modeled, not executed here |
| Assembler copies all event lists | Prevents external mutation of snapshot state |
| Admin snapshot has more detail than user plane | Admin/user boundary is explicit |
