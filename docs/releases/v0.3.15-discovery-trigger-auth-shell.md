# v0.3.15 — Discovery Trigger Auth Shell

## Summary

Adds static Bearer token auth to `POST /api/v1/discovery/trigger`. Token is read from `TRIGGER_AUTH_TOKEN` env var at request time. Missing or wrong token returns HTTP 401. Success response contract unchanged. No JWT, no OAuth, no session/cookie, no full user system.

## Changes

| File | Change |
|------|--------|
| `backend/app/api/deps.py` | New file — `verify_trigger_auth` FastAPI dependency |
| `backend/app/api/discovery.py` | Added `Depends(verify_trigger_auth)` to trigger endpoint |
| `backend/app/core/config.py` | Added `TRIGGER_AUTH_TOKEN` env config entry |
| `backend/tests/api/test_discovery_api.py` | Added 4 new auth tests via `auth_client` fixture |

## Auth Behaviour

| Condition | Result |
|-----------|--------|
| `TRIGGER_AUTH_TOKEN` not set (empty) | Auth not enforced — all requests pass |
| `TRIGGER_AUTH_TOKEN` set, header missing | HTTP 401 |
| `TRIGGER_AUTH_TOKEN` set, wrong token | HTTP 401 |
| `TRIGGER_AUTH_TOKEN` set, correct Bearer token | Fetch-to-discovery chain runs normally |

**Header format:** `Authorization: Bearer <token>`

## Design Decisions

- Token read from `os.getenv("TRIGGER_AUTH_TOKEN")` at request time — allows env override in tests without module reload
- No enforcement when `TRIGGER_AUTH_TOKEN` is empty — shell mode for development; set the env var to activate
- `deps.py` is a dedicated file per FastAPI convention; kept minimal (one function)
- No hardcoded secrets; no JWT; no user DB
