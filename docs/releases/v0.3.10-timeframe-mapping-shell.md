# v0.3.10 — Timeframe Mapping Shell

## Summary

Adds `map_end_date_to_timeframe()` — converts an ISO 8601 date string to a `Timeframe` enum value based on the number of days between the end date and a reference date. Closes the gap between real Polymarket date fields and the system's fixed `Timeframe` enum before trigger wiring. No dependencies beyond stdlib `datetime`.

## Changes

| File | Change |
|------|--------|
| `backend/app/clients/timeframe_mapping.py` | New — `TimeframeMappingError`, `map_end_date_to_timeframe()` |
| `backend/tests/clients/test_timeframe_mapping.py` | New — 15 mapping tests |

## Mapping Contract

**`map_end_date_to_timeframe(end_date, reference_date=None) -> Timeframe`**

| Days remaining | Timeframe |
|---------------|-----------|
| 0–1 | `1D` |
| 2–7 | `1W` |
| 8–30 | `1M` |
| 31+ | `3M` |
| Negative | `TimeframeMappingError` |
| Unparseable | `TimeframeMappingError` |

- `reference_date` defaults to `date.today()` — pass explicit value for deterministic tests
- No silent fallback

## Design Decisions

- stdlib `datetime.date.fromisoformat()` only — no new dependencies
- `reference_date` parameter makes the function fully deterministic in tests
- Returns `Timeframe` enum directly — no string intermediary
