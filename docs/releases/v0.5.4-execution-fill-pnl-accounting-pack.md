# v0.5.4 — Execution Fill + PnL Accounting Pack

## Summary

Introduces execution fill lifecycle accounting and PnL/balance foundation.
Fill-price based PnL calculation. Full trigger/submitted/fill/current separation.
Session balance and session PnL tracking. Event/log record model foundation.
No claim implementation, no sizing, no risk engine.

## Design Decisions

| Decision | Rationale |
|----------|-----------|
| PnL = fill_price based | Binding project decision — order_submitted_price is carried for reporting only |
| trigger / submitted / fill / current separation | These are distinct execution moments, never collapsed |
| unrealized_pnl = 0.0 after exit | Position closed — no unrealized exposure |
| realized_pnl = 0.0 at entry | Position open — not yet realized |
| current_balance = start + session_realized | Unrealized PnL not added to balance until realized |
| claim_adjusted_balance_effect = seam | Field model only; claim logic is future scope |
| EventType covers 11 lifecycle events | Two-phase entry/exit model (submitted → filled) |
| event_record.payload = dict | Flexible for future UI/reporting without schema lock-in |
