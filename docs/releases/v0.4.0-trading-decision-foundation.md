# v0.4.0 — Trading Decision Foundation Pack

## Summary

Introduces the trading entry decision engine. Evaluates whether a market is eligible for entry based on a configurable set of rules. No execution, no simulation — decision only. First version where the system produces a structured "yes/no + why" for a trade.

## Entry Rules

| Rule | Trigger | Pass Condition |
|------|---------|----------------|
| `time_rule` | daily trading window | `trading_start <= current_time <= trading_end` |
| `price_rule` | price/probability range | `price_min <= current_price <= price_max` |
| `move_rule` | PTB-based move | `abs(current_price - ptb) >= move_threshold` |
| `spread_rule` | spread limit | `spread <= spread_max` |
| `event_limit_rule` | daily event cap | `daily_event_count < event_limit` |
| `max_positions_rule` | concurrent position cap | `open_position_count < max_positions` |

## RuleResult Fields

| Field | Description |
|-------|-------------|
| `rule_name` | Identifies the rule |
| `state` | pass / fail / waiting / disabled / locked_by_admin |
| `reason` | Human-readable fail reason |
| `current_value` | Actual measured value for this rule |
| `threshold_value` | Threshold being compared against |
| `distance_to_trigger` | How far from triggering (0.0 when passing) |

## Move Rule Design

- `move = current_price - ptb` — single authoritative formula
- Two-directional: both up and down moves qualify
- Absolute numeric only — no percent mode
- Trigger: `abs(move) >= threshold` (inclusive boundary)
- Same formula used for force sell in v0.5.2

## Rule State Model

| State | Meaning |
|-------|---------|
| `pass` | Rule condition met |
| `fail` | Rule condition not met — blocks trade |
| `waiting` | Condition not yet evaluable (reserved) |
| `disabled` | Rule off — excluded from blocking set |
| `locked_by_admin` | Admin lock — excluded from blocking set (governance in v0.4.1) |
