# v1.0.3 — Order Fill Stream Pack

## Scope

In this version: real order fill stream fetch via HTTP polling, OrderFillStreamResult model, update_type classification, fail-closed error handling.
Not in this version: WebSocket subscription, live testing, frontend changes, simulation path changes.

## New Files

### `backend/app/domain/live/order_fill_stream_payload.py`
Request descriptor for fill stream fetch. Fields: `order_id`, `client_order_id`.

### `backend/app/domain/live/order_fill_stream_result.py`
Result model for order fill stream updates. Fields:
- `order_id` — exchange order id
- `client_order_id` — internal event id
- `update_type` — full_fill / partial_fill / no_update / cancelled / rejected / unknown
- `order_status` — raw status string from exchange (LIVE, MATCHED, CANCELLED, UNMATCHED, DELAYED)
- `filled_size` — filled quantity (populated only when > 0)
- `remaining_size` — remaining quantity
- `fill_price` — fill price from exchange response
- `updated_at` — Unix timestamp string at time of fetch
- `source` — "poll" (HTTP polling path)
- `stream_connected` — True when 200 HTTP response received
- `retryable` — True if transient error
- `terminal_failure` — True if no retry will help
- `reject_reason` — short string reason on failure
- `raw_update_payload` — raw dict from exchange response
- `normalized_update_result` — one-line human-readable summary

## Modified Files

### `backend/app/domain/live/polymarket_http_client.py`
Added:
- `execute_get_fill_stream_update(payload, credentials) -> OrderFillStreamResult`
  - Endpoint: `GET https://clob.polymarket.com/order/{order_id}`
  - Calls signer with `GET` method and `/order/{order_id}` path
  - `PolymarketAuthError` → `_fill_stream_credentials_missing_result()`
- `_parse_fill_stream_response(response, payload) -> OrderFillStreamResult`
  - 200 + status present → classify update_type, populate all fields
  - 200 + status missing → terminal_failure=True, reject_reason="status_field_missing"
  - 404 → update_type="no_update" (order not found, not an error)
  - 401 → terminal_failure=True, reject_reason="auth_error"
  - 429 → retryable=True
  - 400/422 → terminal_failure=True
  - 500/502/503/504 → retryable=True
  - Unknown → terminal_failure=True (fail-closed)
- `_classify_fill_update(status_upper, filled_size, remaining_size) -> str`
  - CANCELLED → "cancelled"
  - UNMATCHED → "rejected"
  - filled > 0 and remaining == 0 → "full_fill"
  - filled > 0 and remaining > 0 → "partial_fill"
  - LIVE/MATCHED/DELAYED with no fill → "no_update"
  - other → "unknown"
- `_fill_stream_credentials_missing_result(payload)`
- `_fill_stream_timeout_result(payload)`
- `_fill_stream_unknown_error_result(payload)`

## Fail-Closed Guarantees

- Missing status field → terminal_failure=True
- Auth error → terminal_failure=True (no fake fill)
- Timeout / 429 / 5xx → retryable=True
- Unknown HTTP → terminal_failure=True
- No fake fill returned on any failure path

## Semantic Validations

- Real order fill stream path exists via `execute_get_fill_stream_update`
- update_type is never faked
- Malformed response is never treated as success
- Auth error is fail-closed
- Timeout / 429 / 5xx are retryable
- source="poll" always set on HTTP path
- No live testing in this version
