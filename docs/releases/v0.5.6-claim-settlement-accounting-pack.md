# v0.5.6 — Claim + Settlement Accounting Pack

## Summary

Introduces claim/settlement lifecycle state evaluation and accounting foundation.
event_outcome_known / resolution_finalized / claim_available gate model.
Claim lifecycle states: available → submitted → completed / failed.
balance_after_claim computed only on CLAIM_COMPLETED.
early_exit_realized_pnl and settlement_effect carried separately — never mixed.
Relayer-compatible claim seam model.
No frontend, no launcher, no live trading, no risk engine.

## Design Decisions

| Decision | Rationale |
|----------|-----------|
| Three-gate model (outcome / resolution / claim_available) | Each represents a distinct lifecycle milestone |
| balance_after_claim computed only on CLAIM_COMPLETED | Prevents premature balance updates |
| early_exit_realized_pnl never added to balance_after_claim | PnL separation is a binding project decision |
| settlement_effect carried separately | Settlement accounting is distinct from position PnL |
| claim_adjusted_balance_effect is a seam field | Set by upstream accounting, not computed here |
| claim_failed checked before claim_completed | Avoids ambiguous state when both flags somehow set |
| No actual relayer API call | Foundation and seam only; relayer integration is future scope |

## Claim Status Values

| Status | Trigger |
|--------|---------|
| `not_claimable_outcome_unknown` | event_outcome_known is False |
| `not_claimable_resolution_pending` | resolution_finalized is False |
| `not_claimable_claim_unavailable` | claim_available is False |
| `claim_available` | All gates passed, no lifecycle flag set |
| `claim_submitted` | claim_submitted=True, not yet resolved |
| `claim_completed` | claim_completed=True |
| `claim_failed` | claim_failed=True |
