# v1.0.2 — Real Balance Fetch + Sync Pack

## Scope

In this version: real balance fetch path added via PolymarketHttpClient, BalanceSyncResult model, fail-closed error handling.
Not in this version: live testing, frontend changes, control plane wiring, simulation path changes.

## New Files

### `backend/app/domain/live/balance_fetch_payload.py`
Minimal request descriptor for balance fetch operations. Carries `currency` field (default: `"USDC"`).

### `backend/app/domain/live/balance_sync_result.py`
Result model for balance fetch + sync operations. Fields:
- `total_balance` — total account balance from exchange
- `available_balance` — balance available to place new orders
- `current_balance` — current balance (available minus reserved)
- `currency` — collateral currency (USDC for Polymarket)
- `synced_at` — Unix timestamp string at time of fetch
- `sync_success` — True only if balance was successfully read
- `retryable` — True if transient error (timeout / 5xx / 429)
- `terminal_failure` — True if no retry will help (auth / malformed)
- `reject_reason` — short string reason when sync_success=False
- `raw_balance_payload` — raw dict from exchange response
- `normalized_balance_result` — one-line human-readable summary

## Modified Files

### `backend/app/domain/live/polymarket_http_client.py`
Added:
- `execute_get_balance(credentials, payload=None) -> BalanceSyncResult`
  - Endpoint: `GET https://clob.polymarket.com/balance-allowance?asset_type=COLLATERAL`
  - Calls signer with `GET` method and `/balance-allowance` path before HTTP call
  - `PolymarketAuthError` → `_balance_credentials_missing_result()` (terminal_failure)
- `_parse_balance_response(response, payload) -> BalanceSyncResult`
  - 200 + valid balance → sync_success=True, all balance fields populated
  - 200 + missing balance field → terminal_failure=True, reject_reason="balance_field_missing"
  - 200 + malformed balance value → terminal_failure=True, reject_reason="balance_field_malformed"
  - 401 → terminal_failure=True, reject_reason="auth_error"
  - 429 → retryable=True
  - 400/422 → terminal_failure=True
  - 500/502/503/504 → retryable=True
  - Unknown → terminal_failure=True (fail-closed)
- `_balance_credentials_missing_result()` — credentials not configured
- `_balance_timeout_result()` — timeout, retryable=True
- `_balance_unknown_error_result()` — unknown exception, terminal_failure=True

## Fail-Closed Guarantees

- Missing or malformed balance field → sync_success=False, terminal_failure=True
- Auth error → sync_success=False, terminal_failure=True (no fake balance)
- Timeout / 429 / 5xx → sync_success=False, retryable=True
- Unknown HTTP error → sync_success=False, terminal_failure=True
- No fake balance is returned on any failure path
- balance=0.0 appears only when exchange returns a real zero balance

- Malformed response is never treated as success
