# v0.3.13 — Trigger-to-Fetch Wiring Shell

## Summary

Wires `POST /api/v1/discovery/trigger` to call `run_polymarket_fetch_to_discovery()`. The old stub/manual-payload path is removed. The endpoint now accepts `source_name`, optional `url`, and optional `timeout`; creates a `PolymarketClient`; and runs the full fetch-to-discovery chain. Errors propagate explicitly as HTTP 502 (client error) or HTTP 422 (mapping/timeframe error).

## Changes

| File | Change |
|------|--------|
| `backend/app/api/discovery.py` | Rewired trigger endpoint to call `run_polymarket_fetch_to_discovery()`; removed manual payload path; added explicit error handling |
| `backend/app/api/schemas/discovery.py` | Replaced `items`-based request (`RawMarketItemSchema` + `items: list`) with `url`/`timeout` fields; removed `RawMarketItemSchema` |
| `backend/app/core/config.py` | Added `POLYMARKET_URL` env config (default: `https://clob.polymarket.com/markets`) |
| `backend/tests/api/test_discovery_api.py` | Replaced 15 old manual-payload tests with 13 new fetch-based tests covering success, error propagation, and validation |

## Request/Response Contract

**Request (new):**
```json
{
  "source_name": "polymarket",
  "url": null,
  "timeout": 10.0
}
```
- `source_name`: optional, default `"polymarket"`, min_length=1
- `url`: optional, falls back to `POLYMARKET_URL` env var
- `timeout`: optional, default `10.0`, must be `> 0`

**Response (unchanged):**
```json
{
  "summary": {
    "added_count": 0,
    "skipped_duplicate_count": 0,
    "skipped_invalid_count": 0,
    "total_seen": 0
  },
  "source_name": "polymarket",
  "ran_at": "2026-04-02T12:00:00+00:00"
}
```

## Error Behaviour

| Error | HTTP Status | Condition |
|-------|-------------|-----------|
| `PolymarketClientError` | 502 Bad Gateway | Network/HTTP failure fetching from upstream |
| `ClientPayloadMappingError` | 422 Unprocessable Entity | Missing required field in upstream row |
| `TimeframeMappingError` | 422 Unprocessable Entity | Past or unparseable `end_date` in upstream data |

## Design Decisions

- `POLYMARKET_URL` lives in `config.py` — no hardcoding in the endpoint handler
- `url` field in request body allows per-request override without changing config
- Old `items`-based path removed entirely — endpoint has one clear purpose
- `RawMarketItemSchema` removed — no longer needed
