# v1.0.4 — Live Execution Driver Pack

## Scope

In this version: LiveExecutionDriver orchestrating full submit → poll → reconcile → orchestrate cycle, LiveExecutionDriverContext, LiveExecutionDriverResult, all sub-layer results wired.
Not in this version: live testing against real exchange, frontend changes, accounting persistence.

## New Files

### `backend/app/domain/live/live_execution_driver_context.py`
Input context for a single live execution driver run. Fields:
- `event_key` — unique run identifier
- `submit_request` — AdapterSubmitRequest
- `credentials` — LiveCredentials
- `outbound_allowed` — guard flag (default False)
- `preflight_passed` — guard flag (default False)
- `max_poll_attempts` — fill stream poll cap (default 1)
- `poll_delay_seconds` — delay between polls (default 0.0)

### `backend/app/domain/live/live_execution_driver_result.py`
Full result of one live execution driver cycle. Fields:
- Identity: `event_key`, `order_id`, `client_order_id`
- Sub-layer results: `submit_result`, `update_result`, `reconciliation_result`, `accounting_result`
- Orchestration: `driver_stage`, `completed`, `retryable`, `terminal_failure`, `blocker_reasons`
- Poll metadata: `poll_attempts`, `last_update_status`
- Fill fields: `last_fill_price`, `last_filled_size`
- Accounting: `realized_pnl`, `unrealized_pnl`, `current_balance`
- Audit: `raw_driver_trace`

### `backend/app/domain/live/live_execution_driver.py`
Orchestrates a single live order execution cycle:
1. Guard check (outbound_allowed + preflight_passed) → PREFLIGHT_BLOCKED
2. Submit via LiveExchangeClient.submit_order()
3. Poll loop via PolymarketHttpClient.execute_get_fill_stream_update()
4. Convert fill stream results to LiveOrderEvents
5. Reconcile events via reconcile_order_events()
6. Build LiveExecutionOrchestrationContext
7. Resolve stage via orchestrate_live_execution()
8. Build accounting summary
9. Return LiveExecutionDriverResult

## Fail-Closed Guarantees

- outbound_allowed=False or preflight_passed=False → PREFLIGHT_BLOCKED immediately
- Submit terminal_failure → TERMINAL_FAILURE, no polling
- Submit retryable → RETRYABLE_FAILURE, no polling
- Poll terminal_failure (auth error / malformed) → TERMINAL_FAILURE, stop polling
- Poll retryable (timeout / 5xx / 429) → RETRYABLE_FAILURE, stop polling
- update_type="unknown" → TERMINAL_FAILURE, stop polling
- No fake success at any step
- All stage values stored as `.value` (Python 3.11+ str,Enum compatibility)
