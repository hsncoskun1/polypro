# v0.5.5 — Order Sizing + Min/Max Order Constraints Pack

## Summary

Introduces order sizing mode selection and admin-controlled constraint enforcement.
Fixed amount and available-balance-percent sizing modes. Min/max order size enforcement.
Minimum available balance to trade check. Disallowed sizing mode block.
Normalized order amount output. No claim, no risk engine, no UI.

## Sizing Result Fields

| Field | Description |
|-------|-------------|
| `size_allowed` | True if order size passes all constraints |
| `normalized_order_amount` | Final computed and rounded order amount (0.0 if blocked) |
| `sizing_reason` | Reason code — success or block reason |

## Sizing Context Fields

| Field | Description |
|-------|-------------|
| `sizing_mode` | SizingMode enum value |
| `available_balance` | Current available balance |
| `total_balance` | Total account balance |
| `policy` | SizingPolicy with admin-controlled constraints |
| `fixed_amount` | Used when mode is FIXED_AMOUNT |
| `available_balance_percent` | Used when mode is AVAILABLE_BALANCE_PERCENT |

## Sizing Policy Fields

| Field | Description |
|-------|-------------|
| `min_order_size` | Minimum allowed order amount |
| `max_order_size` | Maximum allowed order amount |
| `min_available_balance_to_trade` | Min available balance required to enter any trade |
| `allowed_sizing_modes` | List of mode values admin permits |

## Design Decisions

| Decision | Rationale |
|----------|-----------|
| Disallowed mode checked first | Admin policy enforcement takes precedence over balance checks |
| Min available balance checked before amount computation | Prevents meaningless computation when wallet is too thin |
| Zero/negative amount blocked after computation | Fixed amount = 0 or percent = 0 is invalid regardless of constraints |
| Insufficient balance checked before min/max | Balance availability is prerequisite to size constraint validation |
| normalized_order_amount = round(raw, 2) | Consistent decimal precision; avoids floating point artifacts |
| allowed_sizing_modes is a list[str] | Admin can restrict one or both modes |
| claim_adjusted_balance_effect not in scope | Claim logic is future scope |

## Reason Codes

| Reason | Trigger |
|--------|---------|
| `sizing_fixed_amount` | Allowed — fixed amount mode used |
| `sizing_available_balance_percent` | Allowed — percent mode used |
| `disallowed_sizing_mode` | Mode not in policy.allowed_sizing_modes |
| `below_min_available_balance_to_trade` | available_balance < policy.min_available_balance_to_trade |
| `normalized_amount_zero_or_invalid` | Computed amount <= 0 |
| `insufficient_available_balance` | Computed amount > available_balance |
| `below_min_order_size` | Computed amount < policy.min_order_size |
| `above_max_order_size` | Computed amount > policy.max_order_size |
