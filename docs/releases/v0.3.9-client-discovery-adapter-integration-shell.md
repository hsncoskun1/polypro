# v0.3.9 — Client-to-Discovery Adapter Integration Shell

## Summary

Adds `run_polymarket_client_discovery()` — a single-entry integration function that chains `PolymarketClient` → `map_client_rows_to_payloads()` → `map_to_raw_payload_item()` → `PayloadDiscoveryAdapter` → `run_discovery_service()`. Returns `DiscoveryResult`. Errors from client and mapping layers propagate openly. Not wired to the trigger endpoint.

## Changes

| `backend/app/services/discovery_client.py` | New — `run_polymarket_client_discovery()` |
| `backend/tests/services/test_discovery_client.py` | New — 7 integration tests |

## Design Decisions

- New file `discovery_client.py` — not added to `discovery.py` to avoid coupling the adapter-agnostic service with client-specific imports
- `ExternalPayloadMappingError` caught defensively (whitespace-only fields that slip through mapping layer) — no silent loss
- `ClientPayloadMappingError` and `PolymarketClientError` propagate openly to caller
- Not wired to trigger endpoint — integration shell only
