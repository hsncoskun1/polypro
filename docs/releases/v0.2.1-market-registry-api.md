# Release Note — v0.2.1 Market Registry API

## Purpose
Expose the v0.2.0 market registry domain layer through a FastAPI HTTP API.

## What Was Done
- `backend/app/api/schemas/markets.py` — MarketCreate, StatusUpdate, MarketResponse (Pydantic, separate from domain)
- `backend/app/api/markets.py` — markets router: GET /api/v1/markets, GET /api/v1/markets/active, GET /api/v1/markets/{market_id}, POST /api/v1/markets, PATCH /api/v1/markets/{market_id}/status
- `backend/app/main.py` — registry initialized in lifespan as app.state, markets router registered, version bumped to 0.2.1
- `backend/tests/api/test_markets_api.py` — 10 API tests

## Test Summary
- Framework: pytest + FastAPI TestClient
- API tests: 10 / 10 PASSED
- Domain tests: 10 / 10 PASSED
- Health tests: 3 / 3 PASSED
- Total: 23 / 23 PASSED

## API Design Decisions
- Registry stored in `app.state` — no global singleton, no DI framework
- Each test gets a fresh TestClient (context manager) — isolated registry per test
- Request/response schemas are separate from domain models
- Domain errors mapped to HTTP codes: DuplicateMarketError→409, MarketNotFoundError→404, InvalidTimeframeError→422

## Risks / Notes
- In-memory storage — no persistence
- Registry is recreated on each app restart
- No authentication on API endpoints
