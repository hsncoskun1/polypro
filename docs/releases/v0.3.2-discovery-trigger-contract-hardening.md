# v0.3.2 — Discovery Trigger Contract Hardening

## Summary

Hardens the `POST /api/v1/discovery/trigger` request/response contract established in v0.3.1. No new endpoints, no new layers, no domain changes. Changes are confined to `schemas/discovery.py` and `tests/api/test_discovery_api.py`.

## Changes

| File | Change |
|------|--------|
| `backend/app/api/schemas/discovery.py` | `items` required (no default), `min_length=1` on all `RawMarketItemSchema` fields and `source_name` |
| `backend/tests/api/test_discovery_api.py` | Updated existing tests + 7 new hardening tests |

## Contract Changes

### Before (v0.3.1)
| Field | Behaviour |
|-------|-----------|
| `items` | Optional, defaults to `[]` — `{}` body returns 200 |
| `source_name` | Optional, defaults to `"unknown"` — empty string accepted |
| `RawMarketItemSchema` fields | No length validation — empty strings silently fail at normalization layer |

### After (v0.3.2)
| Field | Behaviour |
|-------|-----------|
| `items` | Required — `{}` body returns 422 |
| `source_name` | Optional, defaults to `"unknown"`, `min_length=1` — empty string returns 422 |
| `RawMarketItemSchema` fields | `min_length=1` — empty strings return 422 at API boundary |
