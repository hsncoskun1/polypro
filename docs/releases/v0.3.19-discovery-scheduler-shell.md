# v0.3.19 — Discovery Scheduler Shell

## Summary

Adds a `DiscoveryScheduler` that periodically triggers the discovery chain when enabled. Disabled by default. When enabled, ticks every `DISCOVERY_SCHEDULER_INTERVAL` seconds. Respects the run guard (skips ticks if a run is already in progress), updates run status, and logs errors without crashing.

## Changes

| File | Change |
|------|--------|
| `backend/app/core/scheduler.py` | New file — `DiscoveryScheduler` class |

## Scheduler Behaviour

| Condition | Result |
|-----------|--------|
| `DISCOVERY_SCHEDULER_ENABLED=false` (default) | Scheduler does not start |
| `DISCOVERY_SCHEDULER_ENABLED=true` | Ticks every `DISCOVERY_SCHEDULER_INTERVAL` seconds (default: 3600) |
| Run guard busy on tick | Tick skipped — no new run started |
| Discovery run succeeds | Status updated (`last_success_at`, `last_result_summary`) |
| Discovery run fails | Error logged; `last_error` set; scheduler continues running |
| App shutdown | Scheduler thread stopped cleanly |

## Design Decisions

- `threading.Thread(daemon=True)` — does not block app shutdown
- `threading.Event.wait(interval)` — sleep-based loop; responds to stop signal promptly
- Guard acquire on each tick — prevents overlap with manual trigger calls
- `try/finally` in `_tick` — guard always released; status always reset
- Disabled by default — safe for dev environments without env var set
