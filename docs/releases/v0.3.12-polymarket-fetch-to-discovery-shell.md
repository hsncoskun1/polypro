# v0.3.12 — Polymarket Fetch-to-Discovery Shell

## Summary

Adds `run_polymarket_fetch_to_discovery()` — accepts a `PolymarketClient` instance directly (dependency injection). Keeps `run_polymarket_client_discovery()` as a thin URL-based wrapper that delegates to it. Full chain: client → payload mapping → timeframe mapping → adapter → discovery service.

## Changes

| File | Change |
|------|--------|
| `backend/app/services/discovery_client.py` | New `run_polymarket_fetch_to_discovery(client, registry, ...)` function; `run_polymarket_client_discovery()` now delegates to it |
| `backend/tests/services/test_discovery_client.py` | New `TestRunPolymarketFetchToDiscovery` suite (9 tests with injected mock client); existing URL wrapper tests preserved |

## Function Signatures

**New:**
```python
def run_polymarket_fetch_to_discovery(
    client: PolymarketClient,
    registry: InMemoryMarketRegistry,
    *,
    source_name: str = "polymarket",
) -> DiscoveryResult
```

**Wrapper (unchanged signature):**
```python
def run_polymarket_client_discovery(
    url: str,
    registry: InMemoryMarketRegistry,
    *,
    source_name: str = "polymarket",
    timeout: float = 10.0,
) -> DiscoveryResult
```

## Integration Chain

```
PolymarketClient.fetch()
    → map_client_rows_to_payloads()
    → map_end_date_to_timeframe(pm.end_date)
    → map_to_raw_payload_item()
    → PayloadDiscoveryAdapter
    → run_discovery_service()
    → DiscoveryResult
```

## Error Behaviour

| Source | Error | Handling |
|--------|-------|----------|
| `client.fetch()` | `PolymarketClientError` | Propagates |
| `map_client_rows_to_payloads()` | `ClientPayloadMappingError` | Propagates |
| `map_end_date_to_timeframe()` | `TimeframeMappingError` | Propagates |
| `map_to_raw_payload_item()` | `ExternalPayloadMappingError` | Caught defensively |

## Design Decisions

- Client injection allows callers to control client creation (URL, timeout, headers)
- `run_polymarket_client_discovery()` preserved as convenience wrapper — no breaking change
- No new orchestration layer, no scheduler, no background job
- Trigger endpoint unchanged
