# v0.4.2 — Launcher Readiness + Access Surface Pack

## Summary

Introduces the launcher readiness gate. The application cannot be used meaningfully until all mandatory readiness conditions are met. Fail-closed: any single blocker denies access. No UI in this version — the access decision is authoritative at the domain level and is UI-ready.

## Changes

| File | Change |
|------|--------|
| `backend/app/domain/launcher/readiness_state.py` | New — `ReadinessState` (setup_completed, update_required, preflight_passed) |
| `backend/app/domain/launcher/readiness_result.py` | New — `ReadinessResult` (access_allowed, blocker_reasons) |

## Readiness Gate Model

| Field | Meaning |
|-------|---------|
| `setup_completed` | Initial setup has been completed |
| `update_required` | A mandatory update is pending |
| `preflight_passed` | Preflight checks have passed |
| `access_allowed` | True only when zero blockers remain |
| `blocker_reasons` | List of active blocker identifiers |

## Blocker Identifiers

| Identifier | Trigger |
|-----------|---------|
| `setup_not_completed` | `setup_completed` is False |
| `update_required` | `update_required` is True |
| `preflight_not_passed` | `preflight_passed` is False |

## Design Decisions

| Decision | Rationale |
|----------|-----------|
| Fail-closed gate | Any blocker → access denied; no "partial access" |
| Default state blocks access | `ReadinessState()` defaults produce 2 blockers |
| Access decision is authoritative | Not UI-only gating — domain level decision |
| Runtime state not directly edited | Evaluator reads state as input; no mutation |
| Real update/setup system deferred | Blocker model is in place; implementation in later versions |
