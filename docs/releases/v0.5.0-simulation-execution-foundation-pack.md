# v0.5.0 — Simulation Execution Foundation Pack

## Summary

Introduces the simulation execution foundation — paper trade entry and exit for
simulation mode. Execution comes after the verification gate and does not bypass
it. Fail-safe: never returns None. Duplicate entry protection via in-memory lock
seam. No real DB writes, no force sell, no stop loss, no live trading in scope.

## Execution Model

| Field | Meaning |
|-------|---------|
| `event_key` | Unique market event identifier |
| `side` | Trade direction — "YES" or "NO" |
| `requested_size` | Position size requested by strategy |
| `simulated_fill_price` | Price at which the paper trade is filled |
| `success` | True if execution completed |
| `order_id` | Paper order identifier (PAPER-ENTRY/EXIT-{event_key}-{side}) |
| `fill_price` | Filled price, 0.0 on failure |
| `size` | Filled size, 0.0 on failure |
| `reason` | Empty on success, failure reason on failure |

## Design Decisions

| Decision | Rationale |
|----------|-----------|
| Never returns None | All paths return a fully populated ExecutionResult |
| Duplicate entry blocked | Same event_key cannot be entered twice while locked |
| ExecutionLock as seam | In-memory now; swappable for persistent store in v0.5.2+ |
| Deterministic order IDs | PAPER-{ENTRY/EXIT}-{event_key}-{side} — idempotency-friendly |
| Execution after verification | Does not bypass the verification gate |
| Runtime state passed in | No global mutation — lock is an injected dependency |
| Force sell / stop loss | NOT in scope — v0.5.1+ |
| DB persistence | NOT in scope — v0.5.2+ |
