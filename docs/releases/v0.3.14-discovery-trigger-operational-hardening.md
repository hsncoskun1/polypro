# v0.3.14 — Discovery Trigger Operational Hardening

## Summary

Hardens the `POST /api/v1/discovery/trigger` endpoint introduced in v0.3.13. Adds explicit timeout upper bound, verifies URL fallback and override behavior, and expands the test suite with 5 new targeted tests. No new features, no auth, no scheduler.

## Changes

| File | Change |
|------|--------|
| `backend/app/api/schemas/discovery.py` | Added `le=60.0` to `timeout` field — upper bound of 60 seconds |
| `backend/tests/api/test_discovery_api.py` | Added 5 new tests: zero timeout, max timeout exceeded, config URL fallback, body URL override, timeout wired to client |

## Validation Rules (after hardening)

| Field | Rule |
|-------|------|
| `source_name` | min_length=1 |
| `url` | optional, falls back to `POLYMARKET_URL` env var |
| `timeout` | `gt=0, le=60.0` (must be positive and at most 60 seconds) |

## Error Behaviour (unchanged)

| Error | HTTP Status |
|-------|-------------|
| `PolymarketClientError` | 502 Bad Gateway |
| `ClientPayloadMappingError` | 422 Unprocessable Entity |
| `TimeframeMappingError` | 422 Unprocessable Entity |

  - `tests/api/test_discovery_api.py` — 18 tests (5 new)
  - All other suites — zero regressions
