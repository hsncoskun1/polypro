# v0.3.18 — Discovery Status Auth Shell

## Summary

Adds Bearer token auth to `GET /api/v1/discovery/status`. Uses the existing `verify_trigger_auth` dependency. Behaviour is consistent with the trigger endpoint: fail-closed on missing config, HTTP 401 on missing/wrong token, HTTP 200 on correct token.

## Changes

| File | Change |
|------|--------|
| `backend/app/api/discovery.py` | Added `Depends(verify_trigger_auth)` to GET /status endpoint |
| `backend/tests/api/test_discovery_api.py` | 4 new status auth tests; all existing status GET calls updated with `_AUTH_HEADER`; removed `test_status_endpoint_requires_no_auth` |

## Auth Behaviour (GET /status)

| Condition | Result |
|-----------|--------|
| `TRIGGER_AUTH_TOKEN` not set | HTTP 500 (fail-closed) |
| Token set, header missing | HTTP 401 |
| Token set, wrong token | HTTP 401 |
| Token set, correct Bearer | HTTP 200 — status response |

## Design Decisions

- Reuses `verify_trigger_auth` — no new dependency; trigger and status use the same token
- Consistent with v0.3.15 trigger auth: fail-closed, same error codes
- No separate status token — one token secures both operational endpoints
