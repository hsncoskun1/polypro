# v0.4.3 — Verification Gate Shell

## Summary

Introduces the verification gate as a hard-block layer between strategy entry decisions and execution. Even if strategy reports eligible, verification failure blocks the trade. Fail-closed, no soft warnings, no grace periods. No execution in this version — foundation only.

## Verification Gate Model

| Field | Meaning |
|-------|---------|
| `ref_valid` | Reference data is valid |
| `market_valid` | Market data is valid and available |
| `settings_ok` | Settings are complete and valid |
| `trade_allowed` | True only when all checks pass |
| `blocker_reasons` | List of active blocker identifiers |

## Blocker Identifiers

| Identifier | Trigger |
|-----------|---------|
| `ref_invalid` | `ref_valid` is False |
| `market_invalid` | `market_valid` is False |
| `settings_not_ok` | `settings_ok` is False |

## Design Decisions

| Decision | Rationale |
|----------|-----------|
| Hard-block, no soft warnings | Partial validity is not acceptable |
| Fail-closed gate | Any blocker → trade denied |
| Independent of strategy | Verification is an additional layer, not a replacement |
| Default context blocks all | `VerificationContext()` defaults produce 3 blockers |
| No grace periods | Missing data = no trade, always |
| Runtime state not directly edited | Evaluator reads context as input; no mutation |
