# Iteration — v0.3.16 Discovery Run Guard Shell

## Scope

Adds thread-safe concurrency guard to `POST /api/v1/discovery/trigger`. Prevents multiple simultaneous discovery runs. HTTP 409 on contention. No scheduler, no new auth logic.

## What Changed

- `backend/app/core/run_guard.py`: new `DiscoveryRunGuard` class using `threading.Lock(blocking=False)`
- `backend/app/main.py`: `app.state.discovery_run_guard` initialised at startup
- `backend/app/api/discovery.py`: guard acquire/release around run; HTTP 409 if busy
- `backend/tests/api/test_discovery_api.py`: 3 new guard tests

## Guard Behaviour

| Condition | Result |
|-----------|--------|
| No run in progress | Chain runs normally |
| Run already in progress | HTTP 409 |
| Run completes (success or error) | Lock released via finally |
