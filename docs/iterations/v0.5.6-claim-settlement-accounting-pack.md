# Iteration — v0.5.6 Claim + Settlement Accounting Pack

## Scope

Claim/settlement lifecycle state evaluation and accounting foundation.
Three-gate model: event_outcome_known → resolution_finalized → claim_available.
Full lifecycle: available → submitted → completed / failed.
PnL separation: early_exit_realized_pnl ≠ settlement_effect.
No frontend, no launcher, no live trading, no risk engine, no actual relayer call.

## What Changed

- `claim_status.py`: `ClaimStatus` — 7 lifecycle states
- `claim_context.py`: `ClaimContext` — input with gate fields, lifecycle flags, balance/PnL fields
- `claim_result.py`: `ClaimResult` — output with all settlement accounting fields
- `claim_evaluator.py`: `evaluate_claim_state()` — ordered gate + lifecycle evaluation
- Tests: 30 new in test_claim_evaluator.py

## Architecture

```
ClaimContext (input)
  event_outcome_known, resolution_finalized, claim_available   [gates]
  claim_submitted, claim_completed, claim_failed               [lifecycle]
  balance_before_claim, claimed_amount                         [balance]
  early_exit_realized_pnl, settlement_effect                   [PnL — separate]
  claim_adjusted_balance_effect                                [seam]
        │
        ▼
evaluate_claim_state()
  Gate 1: event_outcome_known?     → NOT_CLAIMABLE_OUTCOME_UNKNOWN
  Gate 2: resolution_finalized?    → NOT_CLAIMABLE_RESOLUTION_PENDING
  Gate 3: claim_available?         → NOT_CLAIMABLE_CLAIM_UNAVAILABLE
  Lifecycle: claim_failed?         → CLAIM_FAILED
  Lifecycle: claim_completed?      → CLAIM_COMPLETED (balance updated)
  Lifecycle: claim_submitted?      → CLAIM_SUBMITTED
  Default:                         → CLAIM_AVAILABLE (is_claimable=True)
        │
        ▼
ClaimResult (output)
  claim_status, is_claimable, balance_after_claim,
  claimed_amount, claim_adjusted_balance_effect,
  early_exit_realized_pnl, settlement_effect, settlement_completed_at
```
