# Iteration Notes — v0.2.9 Market Discovery Pipeline Hardening

## Goal

Harden the pipeline layer against unexpected source behavior and verify summary invariants before any real external source is connected.

## Decisions

- **Fetch result type check in `run_pipeline()`**: raises `TypeError` if `source.fetch()` does not return a `list`. Consistent with the project rule "no silent fallback" — all failures are explicit. Does not catch exceptions from `fetch()` itself (those propagate naturally and are the caller's concern).
- **`total_seen` invariant test**: asserts `added + skipped_duplicate + skipped_invalid == total_seen` across a mixed-input batch. Verifies no count is lost regardless of failure type.
- **Whitespace-only field test**: confirms that a `RawMarketItem` with spaces-only `market_id`, `title`, or `timeframe` is treated as invalid by `normalize_item()` and counted in `skipped_invalid_count`. Previously implied by normalization tests but not tested through the full pipeline.
- **No changes to `normalize.py`, `source.py`, or `discovery.py`**: hardening is confined to `pipeline.py` (one guard) and `test_market_pipeline.py` (four tests).
