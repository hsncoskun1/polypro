# Iteration — v0.7.4 Live Order Response Classification + Fill Confirmation Foundation Pack

## Scope

Response classification, fill confirmation read model, classifier functions.
No live execution. No network calls. Seam for future exchange client.

## What Changed

- `order_response_status.py`: `OrderResponseStatus` — 7 values (submitted → terminal_failure)
- `fill_confirmation_status.py`: `FillConfirmationStatus` — 4 values (not_confirmed → confirmation_failed)
- `live_order_response.py`: `LiveOrderResponse` — response contract with size accounting + failure flags
- `fill_confirmation.py`: `FillConfirmation` — separate read model for fill confirmation lifecycle
- `order_response_classifier.py`: `classify_order_response()` + `build_fill_confirmation()`
- Tests: 39 new in test_order_response.py

## Architecture

```
classify_order_response(raw exchange data)
  Priority:
    terminal_failure → TERMINAL_FAILURE
    retryable        → RETRYABLE_FAILURE
    rejected         → REJECTED
    filled >= req    → FILLED
    filled > 0       → PARTIALLY_FILLED
    acknowledged     → ACCEPTED
    default          → SUBMITTED
        │
        ▼
LiveOrderResponse
  order_id, order_response_status
  requested_size, accepted_size, filled_size, remaining_size
  retryable, terminal_failure, reject_reason
  response_received_at, fill_confirmed_at
        │
        ▼
build_fill_confirmation(LiveOrderResponse)
  terminal_failure  → CONFIRMATION_FAILED
  filled >= req     → FULLY_CONFIRMED
  filled > 0        → PARTIALLY_CONFIRMED
  filled == 0       → NOT_CONFIRMED
        │
        ▼
FillConfirmation (separate read model)
  order_id, fill_confirmation_status
  requested_size, filled_size, remaining_size, fill_confirmed_at
  [future seam → v0.5.3 persistence / v0.5.4 accounting]
```
