# Iteration — v0.3.6 External Payload Adapter Wiring

## Scope

Wires the external payload contract established in v0.3.5 into the live trigger endpoint adapter path. No new domain logic, no new tests, no schema changes.

## What Changed

`backend/app/api/discovery.py` updated so that each item in the trigger request body is:
1. Constructed as `PolymarketMarketPayload` (external format)
2. Mapped via `map_to_raw_payload_item()` to `RawPayloadItem`
3. Collected into a list passed to `PayloadDiscoveryAdapter`

`ExternalPayloadMappingError` is caught defensively — items already pass `min_length=1` at the API boundary, so this path is theoretically unreachable in production but is caught to prevent silent item loss.

## Full Chain (v0.3.6)

```
POST /api/v1/discovery/trigger
         │ RawMarketItemSchema (Pydantic, min_length=1)
         ▼
  PolymarketMarketPayload    ← v0.3.5 (external format)
         │ map_to_raw_payload_item()
         ▼
    RawPayloadItem           ← v0.3.3 (adapter input)
         │ PayloadDiscoveryAdapter.fetch()
         ▼
   run_discovery_service()   ← v0.3.0
         │
         ▼
     run_pipeline()          ← v0.2.8
```
