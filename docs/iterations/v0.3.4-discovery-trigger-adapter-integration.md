# Iteration Notes — v0.3.4 Discovery Trigger Adapter Integration

## Goal

Connect the adapter seam (v0.3.3) to the live trigger endpoint. After this step, the trigger endpoint no longer bypasses the adapter layer — all requests flow through `PayloadDiscoveryAdapter`, making the path consistent from API boundary to pipeline.

## Decisions

- **Single file change**: Only `backend/app/api/discovery.py` modified. No schema changes, no service changes, no domain changes.
- **`StubRawDiscoverySource` removed from endpoint**: No longer needed — `PayloadDiscoveryAdapter` wraps the request payload directly. `StubRawDiscoverySource` remains available in `pipeline.py` for domain-level tests.
- **`RawMarketItem` removed from endpoint imports**: Endpoint now works with `RawPayloadItem` (adapter input type), not the domain normalization input directly. API layer is decoupled from normalization internals.
- **No new tests added**: Existing 15 trigger API tests already exercise all wired behavior. Adding duplicate coverage would add noise without signal.
- **Behavior is identical**: The change is a wiring substitution. All existing contract tests pass unchanged.
