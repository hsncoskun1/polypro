# Iteration — v1.0.9 Admin Entitlement Save Flow + User Visibility Enforcement Pack

## Scope

Admin entitlement editor save/cancel/error flow completion. User panel
entitlement enforcement (visible_panels, trading_enabled, blocked_reason_messages).
No new backend. No trading core changes. No merge.

## What Changed

**Frontend — Admin side:**
- `frontend/src/components/admin/EntitlementEditor.tsx`:
  - `onSave` signature changed: `Promise<void>` → `Promise<{ ok: boolean; error?: string }>`
  - `saveError` state added — inline error shown when save fails
  - `blocked_reason_messages` textarea field added (was hardcoded to [])
  - Cancel resets local form state to original entitlement before closing
  - Save button shows 'Saving...' during request
  - Error cleared on new save attempt

- `frontend/src/routes/AdminPanel.tsx`:
  - `handleSave` now returns `{ ok: boolean; error?: string }`
  - `updateEntitlement` null response (HTTP failure) surfaced as `{ ok: false, error: ... }`
  - `fetchUsers` still called after successful save

**Frontend — User side:**
- `frontend/src/routes/UserPanel.tsx`:
  - Imports and uses `useEntitlement` hook
  - `isPanelVisible()` helper: if visible_panels empty → all panels shown;
    if non-empty → only listed panels shown
  - Trading lock banner shown when `trading_enabled = false`
  - `blocked_reason_messages` shown inside trading lock as list
  - `blocked_reason_messages` shown as amber warning when trading is enabled
  - Panel keys: `positions`, `pnl`, `balance`, `claims`, `live_gate`

**Tests:**
- `frontend/src/test/entitlement-visibility.test.tsx`: 13 new tests

## Architecture Notes

- `visible_rules` / `editable_rules`: stored and passed through; no rules editor
  in current UserPanel UI — enforcement will activate when rules UI is added
- `trading_enabled = false` shows lock but does NOT prevent API calls from
  happening at the backend level — backend enforces via `require_trading_enabled()`
- Admin save failure is surfaced inline in the editor; user does not lose form state
- Session token read from sessionStorage (consistent with useAuth)
