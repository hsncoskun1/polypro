# Iteration Notes — v0.2.6 Market Discovery Source Contract Shell

## Goal

Add a minimal source contract layer so the discovery shell can accept input through a pluggable interface, enabling future replacement of the stub with a real Polymarket adapter without refactoring the discovery logic.

## Decisions

- **`DiscoverySource` Protocol**: single method `fetch() -> list[DiscoveryItem]`. No base class, no ABC — `typing.Protocol` keeps it structural and dependency-free.
- **`StubDiscoverySource`**: wraps a static list. Constructor takes `list[DiscoveryItem]`; `fetch()` returns a shallow copy. Simple, testable, no side effects.
- **`run_discovery_from_source(source, registry)`**: thin wrapper in `source.py` that calls `source.fetch()` then delegates to existing `run_discovery()`. Discovery logic unchanged.
- **No changes to `discovery.py`**: existing `run_discovery(items, registry)` signature preserved. Source contract is additive only.
- **File placement**: `source.py` alongside `discovery.py` in `domain/markets/` — keeps contract in the domain layer, avoids a new top-level module for a small addition.
- **No API wiring**: source contract is domain-only this turn. `main.py` not touched beyond version bump.
