# Iteration Notes — v0.2.3 Market Registry Persistence Shell

## Goal

Add a JSON file persistence layer so market registry state survives server restarts.

## Decisions

- **`JsonMarketStore`** is a plain class with `load()` / `save()` — no ORM, no migration system, no abstraction beyond what the task requires.
- **`MARKET_STORE_PATH`** env var controls file location; defaults to `data/markets.json`. Test isolation uses `tmp_path` fixture.
- **Store integrated in lifespan** (`app.main`): on startup, load file → hydrate registry. On mutation (POST, PATCH), save registry to file.
- **No background sync** — save is synchronous and immediate on every write operation.
- **API test fixture updated**: `client(tmp_path)` sets `MARKET_STORE_PATH` so each test gets an isolated JSON file and a fresh registry.

## Test Coverage

7 unit tests for `JsonMarketStore`:
- load: empty when file missing, saved markets, inactive status, multiple markets
- save: creates parent dirs, overwrites previous, clears on empty list

1 integration test:
- `test_market_persists_across_restart`: two separate `TestClient` context managers against the same file — confirms market created in session 1 is visible in session 2.
