# Iteration — v0.4.1 Rule Governance + Visibility Pack

## Scope

Rule governance and visibility layer. Admin policy controls rule availability, visibility, editability, required state, and locks. User selection is constrained by policy. Rule telemetry model built for user panel. No UI, no execution, no verification gate.

## What Changed

- `rule_policy.py`: `RulePolicyEntry` + `AdminRulePolicy`
- `user_rule_selection.py`: `UserRuleSelection`
- `rule_telemetry.py`: `RuleTelemetryEntry` with all panel-ready fields
- `governance.py`: `validate_user_selection()`, `build_rule_config()`, `build_telemetry()`
- `tests/domain/strategy/`: 36 new tests across 3 files

## Architecture

```
AdminRulePolicy + UserRuleSelection
           │
           ▼
   validate_user_selection()   ← raises ValueError on policy violations
           │
           ▼
   build_rule_config()         ← produces RuleConfig for evaluate_entry()
           │
           ▼
   evaluate_entry(ctx, config) ← v0.4.0 rule engine (unchanged)
           │
           ▼
   build_telemetry()           ← RuleTelemetryEntry list for user panel
           │
           ▼
Verification Gate (v0.4.3)    ← next seam
```
