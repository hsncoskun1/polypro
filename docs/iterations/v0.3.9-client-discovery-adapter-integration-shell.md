# Iteration — v0.3.9 Client-to-Discovery Adapter Integration Shell

## Scope

Connects the previously isolated client (v0.3.7) and mapping (v0.3.8) layers to the discovery pipeline (v0.3.0–v0.3.6) through a single integration function. No trigger endpoint change.

## What Changed

New `backend/app/services/discovery_client.py`:
- `run_polymarket_client_discovery(url, registry, source_name)` orchestrates the full fetch → map → adapt → discover chain
- Placed in services layer — client + mapping imports kept out of the adapter-agnostic `discovery.py`
- Errors propagate openly; `ExternalPayloadMappingError` caught defensively only

## Position in Architecture

```
POST /trigger (v0.3.1–v0.3.6)       run_polymarket_client_discovery()  ← v0.3.9
        │                                         │
        ▼                                         ▼
PayloadDiscoveryAdapter           PolymarketClient → mapping → adapter
        │                                         │
        └──────────────── run_discovery_service() ┘
                                    │
                              DiscoveryResult
```

Trigger endpoint not yet updated — wiring is next step.
