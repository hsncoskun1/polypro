# Iteration Notes — v0.3.0 Discovery Application Service Shell

## Goal

Wrap the pipeline in a stable application service entry point so that API endpoints, schedulers, or admin triggers can call discovery without coupling to pipeline internals.

## Decisions

- **`DiscoveryResult` dataclass**: holds `summary`, `source_name`, and `ran_at`. Keeps metadata separate from `DiscoverySummary` — domain contract unchanged.
- **`source_name` as keyword-only param**: default `"unknown"`, caller supplies a label. Not derived from the source object itself — keeps the service layer simple.
- **`ran_at` as UTC datetime**: uses `datetime.now(UTC)` — timezone-aware, no ambiguity. Set by the service layer, not the pipeline.
- **Service delegates entirely to `run_pipeline()`**: no new discovery logic. Service = envelope + metadata only.
- **New package `backend/app/services/`**: separate from `domain/` — application services are orchestration, not domain logic.
- **`run_pipeline()` and all domain layers unchanged**: service is additive only.
