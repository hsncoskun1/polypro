# Iteration — v0.7.3 Live Order Submission Seam Pack

## Scope

Live order submission seam — request/result contracts, status enum, submission evaluator.
No live execution. No network calls. Future live client connection point.

## What Changed

- `order_submission_status.py`: `OrderSubmissionStatus` enum — 8 outcome values
- `live_order_request.py`: `LiveOrderRequest` — trade intent + guard result booleans
- `live_order_result.py`: `LiveOrderResult` — outcome contract (status, order_id, reject_reason, retryable, terminal_failure)
- `order_submission_evaluator.py`: `evaluate_order_submission()` — guard priority check
- Tests: 28 new in test_order_submission.py

## Architecture

```
LiveOrderRequest (input)
  event_key, market_id, side, requested_size, limit_price
  live_mode_requested
  outbound_allowed       ← from v0.7.2 evaluate_preflight()
  preflight_passed       ← from broader preflight chain
        │
        ▼
evaluate_order_submission()
  Check 1: outbound_allowed=False → SUBMISSION_BLOCKED_OUTBOUND_GUARD
  Check 2: preflight_passed=False → SUBMISSION_BLOCKED_PREFLIGHT
  All pass               → SUBMISSION_READY (submission_allowed=True)
        │
        ▼
LiveOrderResult (output)
  submission_allowed: bool
  order_submission_status: OrderSubmissionStatus
  order_id, reject_reason, retryable, terminal_failure, submit_attempted_at
  [future: live order client populates these fields on actual submission]
```
