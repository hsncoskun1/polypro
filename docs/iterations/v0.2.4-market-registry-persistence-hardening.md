# Iteration Notes — v0.2.4 Market Registry Persistence Hardening

## Goal

Harden the SQLite persistence layer before moving to discovery. Make corrupt data and missing directory scenarios explicit and safe.

## Decisions

- **Corrupt row handling**: `load()` now wraps per-row deserialization in `try/except ValueError`. Bad enum values are logged as warnings and the row is skipped. Valid rows are still returned. This preserves partial data instead of crashing the whole startup.
- **`save()` path safety**: Added `self._path.parent.mkdir(parents=True, exist_ok=True)` to `save()`. This covers the edge case where the directory is deleted between `__init__` and a later `save()` call.
- **No new abstraction**: stdlib `sqlite3` only, no new error types, no generic exception hierarchy. Minimum required change.

## Skipped Test

`test_save_recreates_parent_dir_if_removed` is skipped on Windows (`sys.platform == "win32"`) because Windows file locking prevents `shutil.rmtree` on an open SQLite file. The production safety (`mkdir` in `save()`) is in place. The test passes on Linux/macOS.
