# Iteration Notes — v0.2.4 Market Registry Persistence Hardening

## Goal

Harden the SQLite persistence layer before moving to discovery. Make corrupt data and missing directory scenarios explicit and safe.

## Decisions

- **Corrupt row handling**: `load()` catches `ValueError` from enum construction and re-raises with context: `f"Corrupt market row in DB (market_id={row[0]!r}): {exc}"`. Startup fails explicitly — no silent fallback, no data silently dropped.
- **`save()` path safety**: Added `self._path.parent.mkdir(parents=True, exist_ok=True)` to `save()`. Covers the edge case where the directory is deleted between `__init__` and a later `save()` call.
- **No new exception types**: `ValueError` re-raised with clear message. No custom exception hierarchy needed for this scope.

## Skipped Test

`test_save_recreates_parent_dir_if_removed` is skipped on Windows (`sys.platform == "win32"`) because Windows file locking prevents `shutil.rmtree` on an open SQLite file. The production safety (`mkdir` in `save()`) is in place.
