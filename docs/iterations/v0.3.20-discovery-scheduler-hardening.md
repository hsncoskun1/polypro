# Iteration — v0.3.20 Discovery Scheduler Hardening

## Scope

Operational hardening of the discovery scheduler introduced in v0.3.19. No new features, no new API endpoints, no scheduler behavior changes. Purely defensive guards and validation.

## What Changed

- `backend/app/core/scheduler.py`: `ValueError` on `interval_seconds < 1`; double-start protection via `_thread.is_alive()` check; `_thread = None` after stop
- `backend/app/core/config.py`: `ValueError` on `DISCOVERY_SCHEDULER_INTERVAL < 1` at app startup
- `backend/tests/core/test_scheduler.py`: 8 new hardening tests (16 total)

## Hardening Guards

| Guard | Behaviour |
|-------|-----------|
| `interval_seconds < 1` | `ValueError` at construction |
| `DISCOVERY_SCHEDULER_INTERVAL < 1` | `ValueError` at app startup (config.py) |
| `start()` while thread alive | Logs warning, returns — no second thread |
| `stop()` when not started | No-op, no exception |
| `stop()` twice | Safe — second call is no-op |
| `_thread` after `stop()` | Set to `None` |
| Tick error → next tick | Guard released; scheduler continues |
