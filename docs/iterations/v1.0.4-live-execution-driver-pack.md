# Iteration — v1.0.4 Live Execution Driver Pack

## Scope

LiveExecutionDriver orchestrating full submit → poll → reconcile → orchestrate →
accounting cycle. Accounting stub removed and replaced with real AccountingSnapshot
integration. Two-round delivery: foundation (d9dd04b) + accounting completion (1f8b7d7).

## What Changed

**New backend:**
- `backend/app/domain/live/live_execution_driver_context.py`: input context for a
  single driver run — event_key, submit_request, credentials, guard flags, poll config
- `backend/app/domain/live/live_execution_driver_result.py`: full result of one driver
  cycle — all sub-layer results, stage, fill fields, accounting (Optional[AccountingSnapshot])
- `backend/app/domain/live/live_execution_driver.py`: orchestrates submit → poll loop →
  reconcile → orchestrate → accounting; real compute_entry_fill_accounting() called on fill

**Updated backend:**
- `backend/tests/domain/live/test_live_execution_driver.py`: full driver test suite —
  guard paths, submit terminal/retryable, poll terminal/retryable/unknown, full fill,
  partial fill, cancel, accounting snapshot type/value assertions

## Architecture

```
LiveExecutionDriver.run(ctx)
  ├── Guard check (outbound_allowed + preflight_passed)
  ├── LiveExchangeClient.submit_order()
  ├── Poll loop — PolymarketHttpClient.execute_get_fill_stream_update()
  ├── _to_live_order_event() per poll result
  ├── reconcile_order_events()
  ├── _build_orchestration_ctx()
  ├── orchestrate_live_execution()
  └── Accounting
        filled_size > 0 → compute_entry_fill_accounting(AccountingContext)
        filled_size == 0 → zero AccountingSnapshot
```

## Accounting Integration

Stub (dict with hardcoded 0.0) replaced with real domain types:

| Fill case | Evaluator | Result |
|-----------|-----------|--------|
| full_fill / partial_fill | compute_entry_fill_accounting() | AccountingSnapshot |
| no_update / cancelled / rejected | — | zero AccountingSnapshot |

`realized_pnl`, `unrealized_pnl`, `current_balance` sourced from AccountingSnapshot,
not hardcoded. At entry fill: realized=0.0 (position open), unrealized=0.0
(current_price proxy = fill_price). Session balance fields 0.0 — not available at
driver level (upper orchestration responsibility).

## Fail-Closed Guarantees

- outbound_allowed=False or preflight_passed=False → PREFLIGHT_BLOCKED immediately
- Submit terminal_failure → TERMINAL_FAILURE, no polling
- Submit retryable → RETRYABLE_FAILURE, no polling
- Poll terminal_failure (auth/malformed) → TERMINAL_FAILURE, stop polling
- Poll retryable (timeout/5xx/429) → RETRYABLE_FAILURE, stop polling
- update_type="unknown" → TERMINAL_FAILURE, stop polling
- No fake success at any step
- Live exchange call not made in tests (injectable clients)
