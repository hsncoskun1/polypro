# Iteration — v0.8.4 Backend Release Readiness + Live Test Gate Pack

## Scope

Backend release readiness gate and live test gate models. release_ready and
live_applied_testing_ready are distinct concepts. Live test gate is fail-closed —
explicitly enabled and passed conditions required.

## What Changed

- `backend_release_readiness_context.py`: `BackendReleaseReadinessContext` — 6 chain flags
- `backend_release_readiness_result.py`: `BackendReleaseReadinessResult` — release_ready, blocker_reasons
- `backend_release_readiness_evaluator.py`: `evaluate_release_readiness()` — fail-closed, 6 links
- `live_test_gate_context.py`: `LiveTestGateContext` — release_ready, live_test_gate_enabled, live_test_gate_passed
- `live_test_gate_result.py`: `LiveTestGateResult` — live_applied_testing_ready (fail-closed), blocker_reasons
- `live_test_gate_evaluator.py`: `evaluate_live_test_gate()` — 3-condition fail-closed gate
- Tests: 31 new in test_backend_release_readiness_live_test_gate.py

## Architecture

```
BackendReleaseReadinessContext → evaluate_release_readiness() → BackendReleaseReadinessResult
  final_backend_ready                                             release_ready: bool
  production_wiring_valid                                         blocker_reasons: List[str]
  hardening_ready
  adapter_ready
  concrete_client_ready
  validation_mode_ready

LiveTestGateContext → evaluate_live_test_gate() → LiveTestGateResult
  release_ready                                    live_applied_testing_ready: bool
  live_test_gate_enabled                           blocker_reasons: List[str]
  live_test_gate_passed
```

## Key Invariants

- `release_ready=True` alone does NOT grant `live_applied_testing_ready`
- Gate requires: release_ready AND live_test_gate_enabled AND live_test_gate_passed
- Fail-closed: any missing condition emits a blocker
- live_applied_testing_ready is never auto-propagated
