# Iteration Notes — v0.3.1 Discovery Trigger API Shell

## Goal

Expose `run_discovery_service()` as an HTTP endpoint so it can be called from external systems (admin panels, schedulers, CI) without coupling callers to service internals.

## Decisions

- **`POST /api/v1/discovery/trigger`**: POST semantics — trigger is a command, not a query. Consistent with `/api/v1/` prefix of markets API.
- **Request body carries items**: This shell version accepts raw items in the request body. No real data source integration yet — wiring and contract only.
- **`RawMarketItemSchema` in schemas/discovery.py**: Separate schema from domain `RawMarketItem` — API layer does not expose domain types directly.
- **Inline mapping in endpoint**: `RawMarketItemSchema` → `RawMarketItem` done inline in the endpoint function. No extra mapper layer — only one call site.
- **`StubRawDiscoverySource` reused**: Pipeline's existing stub wraps the request items. No new stub introduced.
- **`app.state.market_registry` from request**: Consistent with markets API pattern — registry accessed via `request.app.state`.
- **`run_discovery_service()` and all layers unchanged**: Endpoint is additive only.
