# Iteration Notes — v0.3.2 Discovery Trigger Contract Hardening

## Goal

Lock down the trigger endpoint's request/response contract before real source integration. Ambiguous validation behavior would compound into harder-to-fix surface area once external callers exist.

## Decisions

- **`items` made required**: Removing the `[]` default forces callers to be explicit. An empty `{}` body should be rejected — it signals an accidental or malformed call, not "run discovery with nothing".
- **`min_length=1` on `RawMarketItemSchema` fields**: Empty strings previously passed API validation and failed silently at normalization (`skipped_invalid_count` incremented). Now they are rejected at the API boundary with 422. This makes the contract unambiguous: invalid inputs are rejected, not swallowed.
- **`min_length=1` on `source_name`**: Empty string label is meaningless. Rejected at API boundary.
- **`source_name` default preserved**: `"unknown"` default retained — omitting source_name is valid (caller doesn't know the source). Empty string is not valid (caller knows but says nothing meaningful).
- **No domain or service changes**: All hardening is at the API schema layer. Domain normalization and pipeline unchanged.
- **Existing tests updated, not replaced**: `{}` body calls updated to `{"items": []}` to reflect the new required field contract.
